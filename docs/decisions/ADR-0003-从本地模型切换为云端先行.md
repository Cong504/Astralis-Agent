# ADR-0003 — 从本地模型切换为云端先行

> 版本：v0.1 ｜ 状态：已接受（2026-11-18，人类决议）｜ 关系：变更 ARCHITECTURE.md §7/§9、PRD.md §6/§7/§8、DEVELOPMENT_PLAN.md W1/W2

---

## 背景

v0.1 原定本地 14B（Qwen2.5-14B + vLLM）为主、云端兜底。实际执行中暴露三点：

1. 本地硬件未就位：当前开发机无 GPU（自检 E01–E03 未通过），3090 主机不可随时访问，本地部署成为关键路径上的阻塞点。
2. W1 目标是验证「输入→计划→确认→执行→日志」闭环，不是验证本地推理；把硬件采购/部署绑在闭环验证前，本末倒置。
3. 云端模型的结构化输出稳定性已被本轮开发验证（Stub 阶段用固定 JSON 跑通全链路），性价比与可用性足以支撑 W1/W2。

---

## 决策

1. **路线改为云端先行**：W1/W2 全部用云端 API 开发与测试。
   - 主用：**DeepSeek**（性价比高、结构化输出稳）。
   - 备选：**Qwen 手动切换**，仅作为「DeepSeek 不可用或需对比时人工改配置切换」，**不做自动互备**。
   - 理由：互备要实现负载均衡、故障切换、一致性校验，第一版没必要；手动切换只需改配置重启，符合最小底盘原则。
2. **本地 LLM 暂缓**：后续硬件候选 RTX 5060Ti 16G 或 V100 32G。选型逻辑：**显存优先于推理速度**——显存决定可加载的量化档位与上下文长度（能不能跑），速度只影响体验且可用量化/并发补偿。`deploy_14b.sh` 保留但标记「待本地硬件就绪后启用」，不再作为 W1 收尾执行项。
3. **Token 监控归属 Runtime 层**（不放在 Model 层）：Model 只负责调用 API 并上报 usage，Runtime 维护 `task_token_budget`，跨多次模型调用累计，超限自动中止任务并告警。阈值写在 `config.json` 的 `runtime.token_budget`（默认 10000 tokens 或 ¥0.5，可配置）。
4. **Interface 层增加等待进度反馈**：云端 API 受网络/限流/排队影响，延迟可能 10–30 秒（远超本地 5 秒目标），需显示「正在思考…已耗时 N 秒」避免用户误判卡死。

---

## 备选

| 备选 | 未采用原因 |
|---|---|
| 继续本地 14B 为主 | 硬件未就位，阻塞 W1/W2 闭环验证；且 14B 规划能力仍是未验证假设 |
| 本地为主 + 云端自动兜底（原方案） | 自动降级需处理后端一致性，第一版过度设计 |
| 双供应商自动互备（负载均衡 + 故障切换 + 一致性校验） | 成本高、第一版用不到；Qwen 改配置手动切换即可 |
| Token 监控放 Model 层 | Model 只处理单次调用，无法跨多次调用累计整个任务的预算 |

---

## 后果

**正面**

- W1/W2 不再被硬件阻塞，云端 API 即开即用。
- 成本护栏（Runtime 层预算）+ 体验护栏（Interface 进度反馈）在切换前就位，避免云端方案的两类典型失控。

**代价 / 新增风险**

- **API 延迟影响体验**：云端 10–30 秒延迟，已列入 PRD §8 风险，缓解为等待进度反馈；PRD 成功标准相应改为「合法率 + 单次延迟上限」而非固定 5 秒。
- **数据出域隐私**：任务文本发往第三方 API，已列入 PRD §8 风险，缓解为「不出域敏感数据 + 沙箱不持有 Key + 日志不记 Key」（SANDBOX_RULES.md §6）。
- **持续成本**：按 token 计费，需 Runtime 预算护栏；DeepSeek 主用控制单价。

---

## 验收证据（2026-11-18）

- 云端路由：DeepSeek 主用 / Qwen 手动切换 / 无 Key 退化为 stub（日志标注 `backend=stub`）。
- Token 监控：`src/runtime/token_budget.py` 累计 usage，超 `runtime.token_budget` 阈值中止并告警。
- 测试：`python -m pytest tests/ -q` 全绿（含预算超限用例）。
